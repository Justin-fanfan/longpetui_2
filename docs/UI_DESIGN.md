# LongPet UI Design System

> 阶段：UI/UX 视觉设计（第一阶段）  
> 目标画布：1024 × 600 px，7 英寸横屏触摸设备  
> 本文只定义视觉与 UI Demo 行为，不包含正式 Qt 页面、业务逻辑或未来接口。

## 1. 产品视觉定位

### 1.1 方向：夜灯暖伴

LongPet 的屏幕首先是机器宠物的脸，其次才是功能界面。视觉方向命名为「夜灯暖伴」：像夜间留在身边的一盏暖色小灯，安静、可靠、有温度，但不过度可爱或幼态。

核心视觉由四部分组成：

- 暖黑石墨背景：避免纯黑带来的生硬，也降低夜间刺激。
- 暖白几何表情：以粗线、圆角、清楚的负形保证远距离识别。
- 单一琥珀强调色：只用于主操作、当前状态和需要注意的信息。
- 大留白与低密度：每屏只保留当前任务需要的信息，拒绝 Dashboard 感。

### 1.2 气质关键词

温和、沉静、可信、精致、克制、适老、陪伴感、轻量。

明确避免：赛博朋克、霓虹蓝、玻璃拟态、复杂渐变、实时模糊、工业仪表盘、手机 App 启动器、开发板演示菜单。

### 1.3 视觉层级

1. 宠物表情或当前安全问题。
2. 一句清楚的状态文案。
3. 当前页面的主要操作。
4. 日期、天气、设备状态等辅助信息。

主页中宠物脸的有效视觉面积应约占屏幕面积的 28%～34%，其中心位于画面水平中轴、垂直约 38% 处。底部三个入口是陪伴动作，不表现为 App 图标宫格。

## 2. 设计原则

### 2.1 脸优先

主页、倾听、思考、说话、睡眠状态都应先看见表情，再看见文字。表情不得被卡片边框、装饰光效或大量数据抢走注意力。

### 2.2 一屏一意图

每个页面只突出一个主要意图。需要比较或编辑的内容最多拆成 3～4 组；不在同一屏同时展示完整历史、统计、设置和操作。

### 2.3 大、少、清楚

- 常规正文不低于 20 px。
- 主操作高度 96 px，紧急操作高度 112 px。
- 老人页面同时出现的主要入口不超过 4 个。
- 每个关键状态同时使用图形、文字和必要的颜色表达。

### 2.4 高级感来自秩序

不使用阴影堆叠、纹理、发光和复杂透明层。高级感来自准确的对齐、固定间距、克制颜色、统一图标和稳定的表情比例。

### 2.5 为低性能平台设计

- 页面以纯色填充、圆角矩形和本地 SVG 为主。
- 同屏透明叠层不超过 2 层；非必要不用半透明。
- 不使用背景视频、粒子、模糊、Shader 或需要 60 FPS 才成立的效果。
- 静态页面本身必须完整成立，动画只补充状态感。

## 3. Color System

所有颜色均为不透明 sRGB 值。除工程演示页的图表外，不扩展新的高饱和功能色。

| Token | 色值 | 用途 |
| --- | --- | --- |
| Background Primary | `#121210` | 全局主背景、主页 |
| Background Secondary | `#191816` | 睡眠以外的次级背景、分区底 |
| Surface | `#23211E` | 卡片、输入区、次级按钮 |
| Surface Secondary | `#2B2925` | 分段控件、选项底、轻强调卡片 |
| Pressed | `#3A352D` | 深色组件按下态 |
| Disabled | `#777168` | 禁用图标和禁用文字 |
| Text Primary | `#F6F1E7` | 主文字、宠物脸 |
| Text Secondary | `#B8B0A3` | 辅助文字、日期、说明 |
| Accent | `#F2B84B` | 主按钮、当前选中、注意焦点 |
| Success | `#82C9A5` | 已完成、正常；必须伴随勾选或文字 |
| Warning | `#E4BE72` | 待处理、提醒；必须伴随时钟或文字 |
| Danger | `#EF7B70` | 紧急、错过；必须伴随警示图形和文字 |
| Divider | `#3C3934` | 1 px 分隔、描边 |

补充固定颜色：

| Token | 色值 | 用途 |
| --- | --- | --- |
| Text on Accent | `#17130B` | 琥珀按钮文字与图标 |
| Text on Danger | `#1B0F0D` | 危险色实心按钮文字与图标 |
| Disabled Surface | `#302E2A` | 禁用按钮底色 |
| Sleep Background | `#0B0B0A` | 睡眠页低刺激背景 |
| Sleep Content | `#8E887E` | 睡眠页时间与表情 |

使用规则：

- 老人页面正文只使用 Text Primary / Text Secondary，不使用灰度更低的文字。
- Accent 不作为大面积页面背景，只用于按钮、选中块和 4～8 px 状态标记。
- Success、Warning、Danger 不单独承担语义，旁边必须有图形或“已完成 / 待完成 / 已错过”等文字。
- 禁用组件使用 Disabled Surface + Disabled，不能只降低透明度，以避免 linuxfb 下表现不稳定。
- 不使用渐变。若需分层，只用 Background、Surface、Divider 三档明度。

## 4. Typography

### 4.1 字体与渲染

中文字体顺序：`Noto Sans CJK SC` → `Microsoft YaHei UI` → 系统无衬线。正式集成前需确认目标系统实际字体文件与中文字重，不依赖网络字体。

所有尺寸均为设计像素 px，不使用 pt。正文默认 Regular 400；按钮、页面标题和关键数据使用 SemiBold 600；不使用超细字重。

| Style | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Status | 20 / 28 | 400 | 日期、天气、设备状态 |
| Status Strong | 24 / 32 | 600 | 状态栏时间 |
| Page Title | 32 / 44 | 600 | 页面标题 |
| Body | 24 / 36 | 400 | 正文、回复内容、主要说明 |
| Assist | 20 / 30 | 400 | 辅助说明、卡片副标题 |
| Button Primary | 28 / 36 | 600 | 主按钮 |
| Button Secondary | 24 / 32 | 600 | 次级按钮、返回文字 |
| Key Data | 40 / 48 | 600 | 时间、关怀重点数字 |
| Pet State | 30 / 42 | 600 | “我在听”“让我想一想” |
| Emergency | 44 / 54 | 600 | 紧急问题 |
| Engineering | 18 / 26 | 400 | 仅工程演示页的密集辅助数据 |

排版规则：

- 中文不使用全大写；英文硬件名可按原拼写。
- 一行主文案建议不超过 18 个汉字；正文最多 3 行。
- 老人页面正文左对齐或居中，不使用两端对齐。
- 数字使用等宽数字特性（若目标字体支持）；时间中的冒号不闪烁也能成立。
- 不用纯颜色、下划线或小字号表现“可点击”，按钮必须有明确容器。

## 5. Spacing

基础间距序列：`4 / 8 / 12 / 16 / 24 / 32 / 40 / 48` px。

| Token | 值 | 典型用途 |
| --- | --- | --- |
| Space 1 | 4 | 微调图形内部距离，不用于页面布局 |
| Space 2 | 8 | 图标内部、状态标签 |
| Space 3 | 12 | 图标与文字、双行文字 |
| Space 4 | 16 | 按钮间、卡片间最小距离 |
| Space 5 | 24 | 卡片内边距、列表项内容间距 |
| Space 6 | 32 | 页面左右安全边距、主分区间距 |
| Space 7 | 40 | 大分区间距 |
| Space 8 | 48 | 紧急页安全边距、视觉舞台留白 |

规则：页面 X 坐标优先落在 32 px 网格；组件内部优先使用 12 / 16 / 24；同层组件间距保持一致，不使用 13、19、27 等孤立值。

## 6. Radius

| Token | 值 | 用途 |
| --- | --- | --- |
| Radius Small | 12 | 状态标签、小型选中块 |
| Radius Medium | 18 | 设置项、列表项、Toast |
| Radius Large | 24 | 主按钮、大卡片、输入区 |
| Radius Pill | 高度的 1/2 | 仅胶囊标签、滑块轨道、状态点 |

圆角不表达可爱感，只降低工业感。宠物表情线端统一为圆帽，线连接统一为圆角。

### 7.2 Primary Large Button

- 默认：Accent 背景、Text on Accent 内容、Radius Large。
- 按下：背景 `#D89D34`，内容整体下移 2 px；不依赖阴影。
- 禁用：Disabled Surface 背景、Disabled 内容；保留清晰标签并可增加“暂不可用”。
- 图标只用 36×36 的统一线性图标，不混用 Emoji。

### 7.3 Secondary / Danger Button

Secondary 用于取消、返回首页、稍后处理。Danger 只用于“联系家人”等确实需要强警示的操作；“我没事”使用 Accent 主按钮，避免两个危险色按钮无法区分。

### 7.4 Back Button

触控区固定 80×80，位于 `x=32, y=68`。可见容器 64×64，居中于触控区。箭头不能单独悬空成为小图标。标题从 `x=128` 开始，避免与返回区域冲突。

### 7.5 Section Card

不使用阴影。默认 Surface，必要时用 1 px Divider。卡片之间至少 16 px；卡片内部至少 24 px。静态内容卡不表现成按钮；可点击卡必须有右箭头和完整触控容器。

### 7.6 Status Bar

固定高度 64 px。左区为日期与时段，中区可显示时间，右区最多放天气、网络/离线、电量和设置入口。只显示少量设备状态，不展示 CPU、RAM 或技术术语。

设置入口触控宽 80 px、高 64 px，是低频辅助入口；老人高频操作仍全部使用底部 96 px 按钮。

### 7.7 Setting Row

标准行高 96 px。滑块可视轨道高 12 px，实际触控区域高 64 px；滑块圆点 32 px。开关高 48、宽 80。数值同时显示文字，例如“声音 60%”，不能只看滑块位置。

### 7.8 Reminder Item

三种状态均用图标 + 标签：

- 已完成：32 px 勾选圆标 + “已完成”。
- 待完成：32 px 时钟圆标 + “待完成”。
- 已错过：32 px 感叹圆标 + “已错过”。

状态色只作为图标与 4 px 侧边标记，不大面积染色。

### 7.9 Toast

用于 UI Demo 的轻确认，例如“已保存这条提醒”。显示 2.5～3 秒，不叠加多个，不承载紧急信息，不要求用户点击关闭。

## 8. Pet Face System

### 8.1 标准画布与比例

- 每个表情统一 `viewBox="0 0 512 256"`。
- 首页显示框：608×296，实际表情绘制区域约 512×240。
- 对话状态显示框：480×220，实际表情绘制区域约 420×196。
- 小型缩略图：128×64；低于此尺寸时去掉眉毛以外的辅助元素。
- 眼睛中心基准：`(156, 104)` 与 `(356, 104)`。
- 嘴部中心基准：`(256, 176)`；宽 112～220，高 24～76。
- 主线宽 30 px；缩略图主线 22 px；辅助元素 10～16 px。
- 所有线端 round、连接 round；主色 Text Primary。
- 表情视觉重心固定在 `x=256, y=132` 附近，左右状态即使不对称也不能偏移超过 20 px。

### 8.2 共同语言

- 眼睛是主情绪来源，嘴巴只补充，不使用复杂脸型或拟人五官。
- 统一采用实心圆角胶囊、粗圆端短线和单段弧线；不再使用空心眼眶或眼眶内瞳点。
- 不画外轮廓、鼻子、牙齿、舌头；避免幼态卡通。
- 默认不加耳朵。Listening 的“耳朵”由两侧声波表达，保持机器宠物抽象感。
- 声波统一为 2～3 条圆角弧线，线宽 12～16，不画音频频谱柱。
- 情绪辅助元素最多 3 个；只使用点、短弧、短线和 `Z`，不使用 Emoji。

### 8.3 十种表情定义

| 状态 | 眼睛 | 眉毛 | 嘴巴 | 辅助元素 | 静态识别重点 |
| --- | --- | --- | --- | --- | --- |
| Default | 两条向中心上扬的粗圆端斜线 | 无 | 大 U 形微笑，宽 196 | 无 | 直接沿用参考图的亲和斜眼语言 |
| Playful | 左眼为实心竖向胶囊；右眼为不对称上扬眨眼弧 | 无 | 偏右的小 U 形 | 无 | 保留原参考图的一实一弯结构 |
| Happy | 两条彼此分离的下弯闭眼弧 | 无 | 宽 220 的大 U 形 | 无 | 眼与嘴均为粗圆端单段曲线 |
| Worried | 两条彼此分离的上弯粗弧 | 无 | 浅倒 U，宽 116 | 无 | 用上弯眼与紧凑嘴形表达担忧，并与 Default 斜眼区分 |
| Sad | 两条向外上扬、向中心下沉的短斜线 | 无 | 较深倒 U，宽 112 | 无 | 不使用眼泪，避免刺激 |
| Sleep | 两条 86 宽下弯闭眼弧 | 无 | 轻微双段波形 | 右上一个简化轮廓气泡和 `Z` | 保留睡眠参考的核心轮廓并显著减点 |
| Listening | 两只 46×70 实心竖向胶囊眼 | 无 | 88 宽浅 U 形 | 左右各 2 条声波弧 | “朝向用户”的专注感 |
| Thinking | 左眼为实心小胶囊；右眼为上扬思考弧 | 无 | 48 宽水平圆角线 | 右上 3 个递增圆点 | 延续 Playful 的不对称几何，不使用加载圈 |
| Speaking | 两只 44×66 实心竖向胶囊眼 | 无 | 72×52 圆角 O 形 | 右侧 3 条不同长度声波 | 实心眼保持交流感，口型和声波表示说话 |
| Alert | 两只 54×78 实心竖向胶囊眼 | 无 | 56×56 圆角 O 形 | 两侧各 1 个 Danger 短括号 | 高警觉但不画惊吓面孔 |

### 8.4 状态色

九个普通状态的脸均使用 Text Primary。Alert 的辅助括号使用 Danger，但眼睛和嘴仍为 Text Primary。Listening / Speaking 的声波可使用 Accent。Sleep 全部使用 Sleep Content。

### 8.5 静态与动画关系

表情必须在动画停止时完整表达状态。眨眼、呼吸、声波只作为增强，不允许通过快速运动才让用户理解“正在听”或“正在说”。

## 9. 页面详细设计

### A. Home

目标：让用户第一眼感到“它在陪我”，而不是看到功能菜单。

- 状态栏：`x=32, y=0, w=960, h=64`。左侧“8月11日 星期二”，中间“15:26”，右侧“晴 27°”、网络/电量和 80×64 设置入口。
- 宠物舞台：`x=208, y=76, w=608, h=296`，无卡片背景和边框；默认表情实际约 512×240。
- 陪伴文案：`x=232, y=376, w=560, h=56`，30 px，居中，例如“下午好，我一直在呢”。
- 主入口：`y=472, h=96`，左右边距 32，间距 16。
  - 陪我说话：`x=32, w=309`，Accent 主按钮。
  - 今日关怀：`x=357, w=310`，Surface 次级按钮。
  - 提醒：`x=683, w=309`，Surface 次级按钮。
- 首页不放应用图标网格、不展示统计数字、不使用轮播。

### B. Listening

- 返回触控区：`x=32, y=68, 80×80`。
- 表情区：`x=272, y=84, w=480, h=220`，Listening 表情，两侧 Accent 声波。
- 状态文案：`x=312, y=304, w=400, h=44`，“我在听”，30 px。
- 识别文本卡：`x=160, y=372, w=704, h=88`，Surface，24 px，示例“提醒我晚上八点吃药”。这是 UI 假文本，不暗示真实识别。
- 取消按钮：`x=384, y=480, w=256, h=88`，Secondary。
- 不显示实时频谱、录音时长、小型工具按钮。

### C. Thinking

- 返回触控区同 Listening。
- 表情区：`x=272, y=112, w=480, h=220`，Thinking 表情。
- 状态文案：`x=272, y=352, w=480, h=48`，“让我想一想……”，30 px。
- 反馈点：3 个 12 px 圆点，间距 16，位于文案下 28 px；静态时使用不同明度，动画时按 12 FPS 缓慢轮换。
- 页面不展示技术加载词、百分比、进度条或转圈加载器。

### D. Speaking

- 左侧宠物区：`x=48, y=136, w=376, h=228`，Speaking 表情。
- 右侧回复卡：`x=456, y=128, w=536, h=244`，内边距 32，正文 26/40，最多 3 行。示例：“好的，晚上八点我会提醒您吃药。”
- 回复卡底部可显示 3 条 Accent 声波弧，不显示音频进度。
- 结束按钮：`x=736, y=472, w=256, h=96`，“回到首页”，Secondary。

## 11. 图标规范

### 11.1 网格

- 源文件统一 `viewBox="0 0 48 48"`。
- 老人页面常规显示 32 / 36 / 40 / 48 px；状态栏可用 28 px。
- 主轮廓线宽 4.5 px，辅助线 3.5 px，round cap / round join。
- 安全区 4 px；图形视觉重心位于 24,24，允许 1 px 光学校正。
- 默认单色 Text Primary；选中图标使用 Text on Accent；状态图标可用 Success / Warning / Danger，但必须配文字。

### 11.2 统一语言

- 天气、提醒、导航都使用“圆角粗线 + 必要的小块面”，不混用一组全填充、一组细描边。
- 同类图标保持相同占框比例：天气 36×36 有效区；提醒 34×34；导航 32×32。
- 晴：圆形太阳 + 8 条短圆角光线。
- 多云：两个重叠圆角云轮廓，不用黑白遮盖造成断裂。
- 雨：云 + 3 枚 45° 圆角雨线，避免复杂水滴。
- 雪：云 + 3 枚六角简化雪花，不使用当前高节点大雪花。
- 大风：3 条不同长度的圆角曲线，去掉装饰圆点和复杂回卷。
- 喝水：杯子轮廓 + 单条水位线；不大面积实心填黑。
- 吃药：45° 胶囊轮廓，中间分割线；避免当前极窄纵向画布。
- 返回、设置、音量、亮度、网络、家人、关于均使用同一 48 网格。

### 11.3 文件规范

- 文件名使用小写英文加连字符，例如 `weather-sunny.svg`、`care-water.svg`。
- SVG 只保留必要 path / circle / line；移除 Illustrator 元数据、空白矩形和无效样式。
- 颜色优先使用 `currentColor` 语义或在资源生成阶段统一为固定 token；不在单个图标里混入任意色值。
- 不嵌入位图、不引用外部 URL、不使用滤镜或蒙版完成基础图形。

## 12. 动画原则

第二阶段实现其中低成本部分；所有动画都必须可关闭并保持静态表达完整。

| 动画 | 建议参数 | 说明 |
| --- | --- | --- |
| 眨眼 | 120～160 ms 闭合；4～7 s 随机间隔 | Default / Listening / Speaking；必须可停 |
| 呼吸 | 2.8～3.6 s；整体缩放 100%→101.5% | 仅 Home / 对话状态 / Gallery 选中表情；Sleep 与 Emergency 关闭 |
| Listening 声波 | 12 FPS；600～800 ms 循环 | 2～3 条弧线依次切换明度 |
| Speaking 声波 | 12～16 FPS；按 3 帧形态循环 | 不绑定真实音频，不做频谱 |
| Thinking 点 | 10～12 FPS；900 ms 循环 | 3 点明度轮换，不旋转 |
| Pressed | 60～90 ms | 改色 + 内容下移 2 px |
| 页面淡入 | 140～180 ms | 仅整体不透明度；可直接关闭 |
| Emergency | 不循环闪烁 | 只保留静态 Danger 条，避免造成焦虑 |

全局目标为 10～20 FPS。动画降级或关闭后，状态含义、布局和可操作性必须完全保留。

## 13. 适老设计原则

1. 高频主要按钮固定 96～104 px 高，紧急按钮 112 px 高。
2. 主页面只有“陪我说话 / 今日关怀 / 提醒”三个主要入口。
3. 不依赖 hover、右键、双击、长按、双指或复杂手势。
4. 单击是唯一基础手势；Sleep 的整屏单击仅用于唤醒 UI Demo。
5. 重要状态同时使用图标、文字和颜色，不只靠颜色。
6. 正文至少 20 px，主正文 24 px；不通过缩小字号容纳过多信息。
7. 每页只保留完成当前任务所需的内容；层级不超过 Home → 列表 → 编辑。
8. 重要功能从 Home 最多 1～2 次点击到达。
9. 高对比同时避免大面积纯白；Text Primary 为暖白，减轻暗环境刺激。
10. 按钮文案使用动词和结果：“保存提醒”“联系家人”，不用技术术语。
11. 错误或紧急提示不自动消失；普通 Toast 才可自动消失。
12. 不使用小型文字链接；返回、取消都有完整触控容器。
13. 不在主要界面使用缩写、英文状态码、CPU/RAM 等工程词汇。
14. 状态变化后给出明确视觉确认，例如勾选图标 + “已保存”。

## 14. 文案原则

语气自然、简短、温和、尊重，不卖萌、不命令用户。

推荐：

- “下午好，我一直在呢”
- “我在听”
- “让我想一想……”
- “今天记得多喝水”
- “好的，我记住啦”
- “晨间用药已经完成”
- “您现在感觉还好吗？”

避免：

- “主人”“宝宝”“亲亲”“么么哒”等幼态称呼。
- “ASR 已激活”“请求处理中”“异常事件触发”等技术化文案。
- “你必须”“赶紧”等命令式文案。

## 15. 参考素材分析与重绘建议

### 15.1 值得保留的语言

- 黑色/白色高对比和极简几何表达。
- 粗线、圆角、少节点带来的远距离识别。
- Default、Happy、Playful 通过极少元素表达情绪的思路。
- 天气与喝水、吃药图形的基本语义轮廓。

### 15.2 不建议原文件直接使用的原因

当前 13 个 SVG 适合作为概念参考，但没有一个建议未经整理直接进入正式资源：

- 画布不统一：多数为 595.28×841.89 纵向画布，吃药为 1700.79×2911.18，实际图形在画布中占比差异很大。
- 颜色不统一：同时出现 `#231815`、`#070604`、`#050202`、白色遮挡块与透明区域。
- 线性语言混杂：部分图标是粗块面，部分是细描边；雨、多云依赖白色遮挡，换到深色背景后不可直接成立。
- 视觉重心不统一：表情眼口间距、整体上下位置、左右占比差异明显。
- 节点复杂度差异大：雪花和睡眠气泡节点非常多，不利于维护与轻量渲染。
- 文件包含 Illustrator 元数据、无效空白路径和接近零高的白色矩形。

### 15.3 分组决策

| 素材 | 决策 | 说明 |
| --- | --- | --- |
| 默认 | 保留语义，重新绘制 | 斜眼微笑有亲和力；统一眼距、线宽与画布 |
| 俏皮 | 保留不对称概念，重新绘制 | 按审核反馈保留实心胶囊眼 + 粗圆端眨眼弧，并统一比例 |
| 高兴 | 保留大笑语义，重新绘制 | 当前嘴部过宽、下坠；收窄并上移视觉重心 |
| 担忧 | 保留眉眼嘴组合，重点重绘 | 当前眼睛过大且像人脸；改为更抽象圆角眼 |
| 低落 | 保留克制语气，重新绘制 | 当前“直线嘴”更像无表情；改为浅倒 U |
| 睡眠 | 保留闭眼 + Z，彻底简化 | 保留参考中的单个气泡轮廓，但改为基础圆角几何和一枚 Z |
| 晴 / 多云 / 雨 | 保留语义轮廓，统一重绘 | 统一 48 网格、4.5 px 主线，不再用白色遮挡 |
| 雪 | 语义保留，图形重构 | 当前大雪花过密；改为云 + 3 枚简化雪花 |
| 大风 | 重新设计 | 当前块面密、方向重心偏；改为 3 条圆角流线 |
| 喝水 | 保留杯形，改为描边体系 | 当前实心面积过大，与导航线性图标不一致 |
| 吃药 | 保留胶囊概念，彻底重导出 | 画布异常且实际图形占比过小；改为 45° 胶囊 |

### 15.4 重绘优先级

1. 十种 Pet Face：决定产品人格，必须先统一。
2. Home 三个入口和 Status Bar 图标：决定首屏完整度。
3. 提醒状态、吃药、喝水：高频且涉及重要状态。
4. 天气图标：统一后再进入状态栏。
5. 设置与工程演示图标：最后补齐，不影响核心陪伴体验。

## 16. 视觉验收清单

进入第二阶段前，用 1024×600 实际截图逐项人工确认：

- Home 第一眼是否先看到宠物脸，而不是三个按钮。
- 1.0 m 距离能否分辨十种表情中的关键差异。
- Text Primary / Text Secondary 在目标面板和暗环境下是否足够清晰。
- 96 px 主按钮是否适合实际 7 英寸触摸，不显拥挤。
- Emergency 的两个按钮是否能在 2 秒内理解，且不误把“联系家人”当取消。
- Care 页面是否像陪伴摘要，而不是健康数据 Dashboard。
- 3 行中文回复、最长设置名称、Reminder Edit 文案是否发生裁切。
- Sleep 的亮度是否足够低，但时间与唤醒提示仍可见。
- 工程演示页的 `DEMO DATA` 是否在任何拍摄角度都明显。
- 所有图标是否来自本地 SVG，且没有外部资源、滤镜和位图嵌入。
